> 做了什么、代码怎么写的、怎么配置、怎么验证、踩了什么坑。
> 项目路径：`E:\Projects\AgentHub`（文中文件引用相对该目录）。

---

## 一、一句话概括

给 Agent 装上了"眼睛"：它现在能**真的去查**目录、容器和服务的状态，
拿到真实证据后再写中文诊断报告——而不是靠猜。

三个新工具（都在 [backend/app/agents/tools/ops.py](backend/app/agents/tools/ops.py)）：

| 工具 | 它回答的问题 | 怎么做到的 |
|---|---|---|
| `check_project` | 项目目录在不在？是什么类型的项目？关键配置文件齐不齐？ | 遍历目录**文件名**（不读内容），按项目类型表判断 |
| `check_docker` | Docker 可用吗？容器在跑吗？健康吗？ | 通过 `/var/run/docker.sock` 只读调用 Docker Engine API |
| `check_service` | 服务活着吗？端口通吗？ | 对**白名单内**的地址发 HTTP GET / TCP 连接，带超时 |

---

## 二、这个功能解决什么问题

改造前，用户问"服务是不是挂了？"，Agent 只能：

- 靠训练数据瞎猜（❌ 不可信）
- 或者用 `web_search` 搜（❌ 搜不到内网服务）

这在实际运维里毫无价值。真正需要的是：

```
用户："帮我看看后端服务是不是挂了"
        ↓
Agent：（真的去连一下 8080 端口，看看返回什么）
        ↓
Agent："服务异常：HTTP 502，耗时 3ms。可能原因：网关上没有可用的后端实例…"
```

**核心变化**：Agent 的回答从"我认为"变成"我查到了"。
这就是所谓的 **Tool Calling（工具调用）**——让模型去调用真实函数，
把函数返回值（证据）作为回答依据。

## 三、设计思路（先看这里，再看代码）

### 3.1 最关键的约束：这个功能会"往外伸手"

普通工具（查时间、算数）怎么乱调都无所谓。但"检查目录/探测端口"不一样：

- 让模型随便传路径 → 它能读宿主机 `/etc/passwd`、数据库密码文件
- 让模型随便传 URL → 它能探测内网、甚至访问云厂商元数据接口偷凭证（**SSRF 攻击**）

所以本功能的每条能力都是**白名单制**，共 4 条安全规则：

| 规则 | 实现位置 | 效果 |
|---|---|---|
| ① 路径白名单 | `_resolve_allowed_path()` [ops.py:237](backend/app/agents/tools/ops.py#L237) | 只能查 `OPS_PROJECT_ROOTS` 里的目录；先 `resolve()` 再比对，`../` 和软链接都逃不出去 |
| ② 地址白名单 | `_host_allowed()` [ops.py:707](backend/app/agents/tools/ops.py#L707) | 临时目标必须命中 `OPS_ALLOWED_HOSTS`（默认**空 = 全禁用**） |
| ③ 元数据地址永久封禁 | `_METADATA_HOSTS` [ops.py:84](backend/app/agents/tools/ops.py#L84) | `169.254.169.254` 等云元数据地址，就算白名单写了也拒绝 |
| ④ 不泄露密钥 | `_redact()` / `_redact_url()` [ops.py:304](backend/app/agents/tools/ops.py#L304) | 报告里的 URL 去掉 query 参数、响应体里的 `api_key/token/password` 打码 |

**记住一句话**：URL 由运维在 `.env` 里配置，模型只能**按名字**引用
（`check_service("backend")`），不能自己编造地址。这是本功能安全的根本。

### 3.2 项目类型表：为什么不能"机械要求所有文件都存在"

新手最容易写错的做法：

```python
# ❌ 错误示范：不管什么项目都要求这些文件
for f in ["requirements.txt", "package.json", "go.mod"]:
    if not exists: 报错
```

Go 项目永远没有 `requirements.txt`，Node 项目永远没有 `go.mod`——
这样写会把健康项目全判定为异常。

正确做法是**先识别项目类型，再按该类型检查**（[ops.py:120](backend/app/agents/tools/ops.py#L120)）：

```python
@dataclass(frozen=True)
class _ProjectType:
    name: str          # "python"
    label: str         # "Python 项目"
    markers: tuple[str, ...]        # 命中任一 → 判定为该类型
    required_any: tuple[tuple[str, ...], ...]  # 每组至少存在一个
    recommended: tuple[str, ...]    # 建议有，缺了只提示不报错
```

两个设计细节值得学：

1. **`markers` 故意比 `required_any` 宽**。比如 Node 项目的 markers 包含
   `package-lock.json`，但关键文件要求 `package.json`。
   这样"有锁文件却没有 `package.json`"这种**残缺检出**就能被抓出来——
   这正是检查器存在的意义。
2. **`required_any` 是"组"**。Python 项目的依赖清单可以是
   `pyproject.toml` / `setup.py` / `requirements.txt` / `Pipfile` 任意一种，
   要求"至少有一个"才合理。

`recommended`（README、.gitignore 等）缺失只降级为提示，状态是"正常（有提示）"，
不会误报为异常。

### 3.3 Docker 检查：为什么不用 docker 命令行

backend 容器里**没有装 docker CLI**，但 Docker 守护进程本身就是个 HTTP 服务器，
监听在 `/var/run/docker.sock` 这个 Unix socket 上。

所以直接发 HTTP 请求即可，用已有的 `aiohttp`（[ops.py:533](backend/app/agents/tools/ops.py#L533)）：

```python
connector = aiohttp.UnixConnector(path=socket_path)   # 走 Unix socket，不走 TCP
async with aiohttp.ClientSession(connector=connector) as session:
    async with session.get(f"http://localhost{endpoint}") as resp:
        return json.loads(await resp.text())
```

好处：**零新增依赖**（aiohttp 本来就在 requirements 里）、不用 apt 装 docker-cli。
代码里只发 **GET** 请求，永远不 start/stop/remove，所以是"只读"的。

### 3.4 为什么工具返回中文

其他工具（如 `save_memory`）返回英文，但这三个工具返回中文，原因很实际：
它们的输出会**直接作为证据**出现在中文诊断报告里，模型不用再翻译一遍，
状态词（健康/异常/已拒绝）也不会在转换中失真。

代码注释保持英文，与项目其他文件一致；只有**面向用户的输出**用中文。

### 4.1 完整数据流（用户问"服务健康吗"）

```
用户："帮我做一次完整的服务健康检查"
   │
   ▼
前端 SSE ──► FastAPI /api/v1/chat/{thread_id}/stream
   │
   ▼
LangGraph Agent（backend/app/agents/supervisor.py 启动时构建）
   │
   │  supervisor_prompt 中间件注入系统提示词
   │  （含 supervisor.md 里的"Ops Diagnosis Report"格式要求）
   ▼
模型判断："这是运维检查，该调工具" ──► 发出 tool_call
   │
   ├─► check_project(path="/ops/projects")        ─┐
   ├─► check_docker(containers="agenthub-backend") │ ToolNode 逐个执行
   └─► check_service(target="backend")            ─┘
   │                                                 │
   │        ┌────────────────────────────────────────┘
   │        ▼
   │   工具内部执行：
   │     check_project → Path.resolve() 校验白名单 → iterdir() 列文件名
   │     check_docker  → aiohttp UnixConnector → GET /version、/containers/json
   │     check_service → aiohttp GET（带超时、不跟随跳转、不存 cookie）
   │        │
   │        ▼
   │   返回中文证据文本（含 ✓/✗/! 标记）
   │
   ▼
模型拿到三份证据 ──► 生成中文报告（总体状态/检查证据/可能原因/处理建议）
   │
   ▼
前端显示报告 + 右侧 DAG 面板可视化每次工具调用
```

### 4.2 三个工具内部的判断流程

```
check_project(path)
   ├─ path 为空 → 列出所有允许的根目录（让模型知道有什么可查）
   ├─ resolve 后不在白名单 → 「已拒绝」+ 告诉用户怎么配置
   ├─ 目录不存在 → 「异常」+ 顺手列出上一级的兄弟目录（拼错时很有用）
   ├─ 存在但不是目录 → 「不是目录」
   └─ 正常 → 识别类型 → 查关键文件/建议文件/子项目 → 「正常 / 正常（有提示）/ 异常」

check_docker(containers)
   ├─ socket 文件不存在 → 「不可用」+ 给出 docker-compose 挂载写法
   ├─ socket 存在但连不上 → 「不可用」+ 提示守护进程/权限问题
   ├─ 访问 /version 失败 → 报具体错误
   └─ 成功 → 汇总所有容器 / 逐个核对指定容器（支持唯一前缀匹配）

check_service(target)
   ├─ target 为空 → 列出所有已配置目标 + 临时目标是否启用
   ├─ 命中配置名 → 用运维配置的 URL（可信）
   ├─ 未命中 → 当临时目标：校验协议/凭据/端口 → 校验主机白名单 → 校验元数据黑名单
   ├─ 协议 http/https → GET（2xx/3xx=健康），超时/连接失败=异常
   └─ 协议 tcp → asyncio.open_connection 探测端口
```

## 五、修改文件清单（9 个文件）

### 5.1 新增：`backend/app/agents/tools/ops.py`（约 945 行，核心）

三个工具 + 全部安全校验。关键代码节选：

**① 路径白名单校验**（[ops.py:237](backend/app/agents/tools/ops.py#L237)）：

```python
def _resolve_allowed_path(raw_path: str) -> tuple[Path | None, str]:
    """返回 (已解析路径, "") 表示允许；返回 (None, 原因) 表示拒绝。"""
    roots = _configured_roots()
    if not roots:
        return None, "服务端未配置允许检查的目录（OPS_PROJECT_ROOTS 为空）……"

    # 先 resolve：把 ../ 和软链接都展开成真实路径
    candidate = Path(raw_path).expanduser().resolve()

    # 再判断是否在任一允许的根目录下
    if not any(_is_within(candidate, root) for root in roots):
        return None, f"路径不在允许检查的范围内，已拒绝：{candidate}……"
    return candidate, ""
```

> `_is_within()` 用了 `os.path.normcase()`——因为 Windows 路径不区分大小写，
> 直接比字符串在 Windows 上会误判。

**② 主机白名单 + 元数据封禁**（[ops.py:707](backend/app/agents/tools/ops.py#L707)）：

```python
def _host_allowed(host: str) -> tuple[bool, str]:
    if host.lower() in _METADATA_HOSTS:          # 云元数据地址，永久拒绝
        return False, f"{host} 是云厂商元数据地址，出于安全考虑一律拒绝。"

    allowed = get_settings().ops_allowed_hosts_list
    if not allowed:                               # 默认空 = 临时目标全禁用
        return False, "服务端未配置 OPS_ALLOWED_HOSTS，因此拒绝任何临时目标……"

    for entry in allowed:
        if entry.strip().lower() == host.lower():
            return True, ""                       # 精确匹配主机名/IP
        try:                                      # 也支持 CIDR，如 10.0.0.0/8
            if ipaddress.ip_address(host) in ipaddress.ip_network(entry, strict=False):
                return True, ""
        except ValueError:
            continue
    return False, f"主机 {host} 不在允许清单 OPS_ALLOWED_HOSTS 中。"
```

**③ Docker API 只读调用**（[ops.py:533](backend/app/agents/tools/ops.py#L533)）：
见 3.3 节的代码。返回值约定 `(数据, 错误信息)`，**永不抛异常**——
工具抛异常会让整轮对话失败，返回"人话错误"才能让模型继续解释。

**④ 密钥打码**（[ops.py:94](backend/app/agents/tools/ops.py#L94)）：

不挂载的话 `check_project` / `check_docker` 永远只能返回"不可用"。

```yaml
    environment:
      OPS_PROJECT_ROOTS: /ops/projects     # 与下面的挂载路径对应
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro         # Docker 检查

```

- `:ro` = read-only，容器只能读不能写

### 8.3 测试怎么做到"不依赖环境"的

新手写测试最常见的坑是"测试依赖本机状态"（比如必须有 Docker 才能跑）。
本套件用两个夹具解决（[conftest.py](backend/tests/conftest.py)）：

```python
@pytest.fixture
def configure_ops(monkeypatch):
    """把 ops 模块里的 get_settings 换掉，每个测试自己决定白名单内容。"""
    def _configure(**overrides):
        settings = _fake_settings(**overrides)
        monkeypatch.setattr(ops_module, "get_settings", lambda: settings)
        return settings
    _configure()          # 默认：最严格的配置（什么都不允许）
    return _configure
```

测试里就这样用：

```python
async def test_check_service_http_healthy(configure_ops, http_port):
    configure_ops(endpoints={"web": f"http://127.0.0.1:{http_port}/health"})
    report = await check_service.ainvoke({"target": "web"})
    assert "总体状态：健康" in report
```

`monkeypatch` 会在测试结束后**自动还原**，不会污染其他测试。

## 九、常见问题（FAQ）

### Q1：Agent 说 "Docker 不可用"，怎么办？

按顺序查：

```bash
# ① 宿主机上 Docker 本身是否在跑
docker version

# ② 容器里 socket 挂上没
docker exec agenthub-backend ls -la /var/run/docker.sock
# 报 "No such file or directory" → docker-compose.yml 里少了挂载，改完 up -d

# ③ 后端日志里的具体错误
docker logs agenthub-backend 2>&1 | grep -i docker | tail
```

### Q2：问它检查某个目录，它说"路径不在允许检查的范围内"

这是**设计如此**，不是 bug。两种解法：

1. 把目录挂进容器 + 加进白名单（见 6.3 节）
2. 直接把路径挂到已有的 `/ops/projects` 下面

### Q3：`check_service` 说 "已拒绝…OPS_ALLOWED_HOSTS"

默认**禁止一切临时目标**（防 SSRF）。要么用 `.env` 里 `OPS_HEALTH_ENDPOINTS`
配置的**名字**调用，要么把主机加进 `OPS_ALLOWED_HOSTS`。

### Q4：改了代码为什么没生效？

后端代码是 **COPY 进镜像**的，改完必须重建：

```bash
docker compose build backend && docker compose up -d backend
```

只 `docker compose restart backend` 不会重新打包代码。

### Q5：跑测试报 `No module named pytest`

测试依赖不在生产镜像里（故意的）。用脚本跑，它会自动装：

```bash
docker exec -w /app agenthub-backend bash scripts/run_tests.sh
```

装了 pytest 后如果**重建过容器**，pytest 会随旧容器一起消失，
再跑一次脚本即可（脚本会自动重装）。

### Q6：健康检查里为什么看不到响应正文？

如果返回的是 HTML（比如访问前端 nginx 首页），工具会写
"响应为 HTML 页面（已省略正文）"——整页 HTML 在诊断报告里纯属噪音。
JSON 接口的响应会显示前 200 字符，且 `api_key/token/password` 等字段会被打码成 `***`。

### Q7：怎么关掉这组工具？

`.env` 里 `OPS_ENABLED=false`，重启后端。日志会打印
`Ops tools disabled (OPS_ENABLED=false)`。

### Q8：挂载 docker.sock 安全吗？

必须知情：**能访问 docker.sock 就等于能以 root 操作宿主机**（可以起特权容器）。
本功能的安全边界在于：

- 代码**只发 GET 请求**，没有任何 create/start/stop/remove
- `:ro` 挂载（虽然 socket 的 `:ro` 对 API 调用限制有限，见下）
- 工具不暴露给外部 HTTP 接口，只有登录用户通过 Agent 触发

**如果你的环境不能接受这个风险**：把 `OPS_DOCKER_SOCKET` 指到一个不存在的路径，
`check_docker` 就会返回"不可用"，其余两个工具不受影响。

## 十、当前限制（必须知道的）

| 限制 | 说明 | 后续可改进方向 |
|---|---|---|
| **临时目标默认全禁用** | `OPS_ALLOWED_HOSTS` 为空时，只能查 `.env` 里配置好的名字 | 需要临时排查时手动加白名单；或做一个"限时授权"机制 |
| **不做 DNS 解析校验** | 白名单匹配的是**主机名/IP 字面量**，不解析后比对 IP。理论上存在 DNS rebinding 绕过（`evil.com` 解析到 `169.254.169.254`） | 白名单里只写 IP/CIDR；或在请求前解析并二次校验 IP（注意 TOCTOU） |
| **只检查目录，不检查内容** | `check_project` 只看**文件名**，不读文件内容、不校验 YAML/JSON 语法 | 可加"配置文件语法校验"（只读 content-type 安全的文件） |
| **子项目只扫一层** | `monorepo/packages/a/` 这种三级结构不会被识别 | 改成可配置深度的递归扫描 |
| **Docker 检查限于本机守护进程** | 通过本地 socket 连接，无法管理远程 Docker / K8s | 加 `DOCKER_HOST=tcp://…` 支持；K8s 另做一套工具 |
| **没有历史/趋势** | 每次都是"此刻快照"，不存历史、不告警、不做趋势 | 落库到 `trace_executions` 同款表 + 定时任务巡检 + 阈值告警 |
| **不自动修复** | 全程只读，发现问题只给建议 | 高风险操作（重启容器等）需要另设计审批流，不建议直接开放给模型 |
| **`check_docker` 的 `:ro` 不是真隔离** | Unix socket 的 `:ro` 挂载挡不住写操作，真正的保证来自"代码只发 GET" | 可用 docker-socket-proxy 做**真正的 API 白名单**（推荐生产使用） |
| **容器内文件系统视角** | `/ops/projects/backend` 是**挂载进容器后**的路径，和你 Windows 上的 `E:\Projects\AgentHub\backend` 是同一份文件但路径不同 | 文档里说明清楚即可；回答用户时注意别混淆 |

## 十一、学习要点（面试可讲）

1. **工具的安全边界 = 白名单 + 参数注入**。模型能控制的只有"名字"和"开关"，
   真正的地址/路径来自服务端配置。这是所有"让 LLM 访问外部资源"场景的通用解法。

2. **`@tool` 装饰器把普通函数变成模型可调用的工具**，函数的 **docstring 就是
   给模型看的说明书**——所以本次 docstring 用中文写清楚了每个参数的含义和返回值，
   模型据此决定怎么调用。

3. **工具永不抛异常**：返回 `(数据, 错误信息)` 二元组。工具抛异常会让整轮对话
   崩掉，返回"人话错误"则能让模型继续推理并给出建议。

4. **"不机械要求所有文件"的本质是"先分类，再按类判断标准"**。这个思路适用于
   一切检查类需求（代码规范检查、部署检查、合规检查）。

5. **Docker 守护进程就是个 HTTP 服务**，`aiohttp.UnixConnector` 就能直接对话，
   不用装 docker CLI，也不用加依赖。

6. **测试要能在任何机器上跑**：`monkeypatch` 换配置 + 临时起本地服务器，
   比"要求本机必须有 Docker"可靠得多。

7. **把"安全拒绝"设计成一等公民**：拒绝也是**结果**，要如实汇报、要告诉用户
   怎么配置才能放行。提示词里明确写"不许绕过、不许谎称成功"，
   否则模型很可能编造一个"检查通过"。
